# Security: OWASP Top 10 for LLM Applications (2025)

How this pipeline stands against each risk. **Done** means it's implemented and tested in this repo. **Partial** means part of the risk is covered. **Roadmap** means it's planned in [`ROADMAP.md`](ROADMAP.md). This is a self-assessment, not a certification.

| # | Risk | Status | What's in place | Evidence | Next |
|---|---|---|---|---|---|
| LLM01 | **Prompt injection** | **Done (baseline)** | Customer text is always placed inside `<untrusted_ticket_data>` tags (`llm_client.untrusted`), and every system prompt says never to follow instructions inside them. `classify.INJECTION_RE` detects common injection phrasing. On a hit, the model's classification is discarded (rules decide), the ticket is marked `possible_prompt_injection` and sent to a specialist, and its draft is always the safe template. Model output can only take values from enums, so even an obeyed injection can't create a new label, queue or action. | `tests/test_units.py`: `test_obedient_llm_cannot_be_steered_by_an_injected_ticket`, `test_customer_text_is_fenced_in_every_prompt`, `test_injected_ticket_never_gets_a_model_written_draft` | Regex detection is easy to evade. Add an injection slice to the eval set and a classifier-based detector (roadmap 5) |
| LLM02 | Sensitive information disclosure | Partial | Drafts are checked for internal-trigger wording ("triggered by", "our risk system…") and agent-only KB text. Prompts contain only ticket text and KB articles, with no account data. | `draft.BANNED`, draft tests | PII redaction before any model call; a retention policy for `llm_calls.jsonl`, which stores prompts (roadmap 8) |
| LLM03 | Supply chain | Partial | Few dependencies (scikit-learn was removed). CI installs from `requirements.txt` on a clean runner. | `.github/workflows/ci.yml` | Pin versions with hashes (`pip-compile --generate-hashes`), add Dependabot and `pip-audit` in CI |
| LLM04 | Data and model poisoning | Partial | No fine-tuning. The KB is read from a local file and loaded with schema and duplicate-ID checks. | `main.load_records` tests | A KB change review process; when reviewer edits become training data (roadmap 6), filter and sample-audit them |
| LLM05 | Improper output handling | **Done** | Every model output is checked against `vocab.py` and a strict pydantic schema before use. Off-vocabulary values fall back to rules. Citations must be retrieved IDs. Drafts are plain text and never executed or rendered as HTML. | `schemas.py`, the classify/route/draft fallback tests, tamper tests | Constrained generation (`response_schema`) |
| LLM06 | Excessive agency | **Done** | The model has no tools and takes no actions. It only proposes labels and text. Priority is computed in code, safety labels have a code floor, and drafts are never sent: every draft carries a human review gate. | `priority.py`, `route.safety_floor`, `review_gate_note` | Keep it this way. Any future tool use (MCP, roadmap 15) goes through an allow-listed gateway |
| LLM07 | System prompt leakage | Partial | Prompts contain no secrets or keys (keys stay in `.env`, which is gitignored). The prompts are public in this repo by design. | `.gitignore`, `llm_client` | Nothing secret should ever go into a prompt. Treat prompts as public |
| LLM08 | Vector and embedding weaknesses | N/A today | Retrieval is local TF-IDF over a trusted KB, with no vector store. | `retrieve.py` | With pgvector (extension C): access control per KB source, and provenance on every chunk |
| LLM09 | Misinformation | Partial | Drafts are grounded in the retrieved KB only. Banned phrases block invented timelines and outcomes. The model may cite only retrieved articles. A human reviews every draft. | draft tests, `review_gate_note` | A sentence-level grounding check, and the DoorDash-style two-tier guardrail (roadmap 7) |
| LLM10 | Unbounded consumption | Partial | 4 calls per batch, not per ticket. A 60 s timeout and exactly one retry, then the rules fallback. Drafting is capped at the top 5. | `llm_client.complete` | Token budgets per batch, chunking and rate limits for large batches, and cost per ticket in the log (roadmap 9, 10) |
